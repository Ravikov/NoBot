# WebSocket 协议说明

## 概述

NoBot 的 WebSocket 服务运行在 **`ws://0.0.0.0:7323`**。如果端口被占用，会自动递增直到找到可用端口。

主要用于：
- 自定义客户端接入
- ESP32 硬件控制（NoBot-esp32）

## 连接

```
客户端 → ws://服务器IP:7323
```

首次连接时，ESP32 需发送能力表（type 100），NoBot 写入 `actionAndHardware.txt`。

## 消息格式

所有消息为 **JSON 字符串**。

### 客户端 → 服务端

#### 普通文本消息

```json
{
  "msg": "你好",
  "type": 1,
  "media": null
}
```

#### ESP32 首次连接（上报能力）

```json
{
  "msg": "action:\n    LED_GLOW\nhardware:\n    RED_LED",
  "type": 100
}
```

#### ESP32 控制请求

```json
{
  "msg": "请点亮红色LED",
  "type": 101
}
```

### 服务端 → 客户端

#### 文本回复

```json
{
  "msg": ["回复内容1", "回复内容2"],
  "type": 1,
  "delay": 0.5
}
```

#### ESP32 指令回复

```json
{
  "msg": [{"msg":"完成","action":0,"hardware":0}],
  "type": 1,
  "delay": 0
}
```

## 消息类型对照

| type | 方向 | 说明 |
|---|---|---|
| 1 | 双向 | 普通文本消息 |
| 2 | 客户端 → 服务端 | 图片消息（含 base64） |
| 5 | 客户端 → 服务端 | 视频消息（含 base64） |
| 9 | 客户端 → 服务端 | 多条消息合并（B 段消息） |
| 100 | ESP32 → 服务端 | ESP32 首次连接，更新能力表 |
| 101 | ESP32 → 服务端 | ESP32 硬件控制请求 |
| 105 | 客户端 → 服务端 | 包含 ESP32 控制指令的复合消息 |

## 消息分段

LLM 回复可能包含多条消息，用 `#` 分隔：

```
回复1#回复2#回复3
```

服务端会按 `#` 切分后以数组形式返回。
